## 网站编辑与复制

在项目目录运行 `python tools/web_server.py --port 56717`，打开 <http://127.0.0.1:56717/>。

1. 选择专精和大秘境副本。
2. 在“首领”下拉框选择要配置的首领，再点击“添加提醒”。切换首领保留该副本的其他配置；技能和物品可填写编号，饰品选13/14槽位。
3. 选择开战或已接入事件、第一次／指定次数／每次、延后秒数和保留窗口。首次使用后要持续提醒的技能，勾选“后续冷却就绪提醒”。
4. 点击“生成字符串”。空白首领不生成动作；整份为空或含无效规则时拒绝生成。
5. “复制字符串”→ 游戏 `/nr` → 粘贴 → 检查导入 → 保存并启用。新文本要求0.3.0或之后的插件；旧单首领NRPlan仍可导入。

修改配置立即清掉旧生成文本并禁用复制，须重新生成。保存草稿只保存到本机浏览器，不等于已导入游戏；旧的单首领已保存草稿可迁移，原存储保留。

整副本导入只替换**此专精、此副本的大秘境首领事件方案**，未配置首领的旧事件规则清除，并保存整包备份。暂停和回滚作用于最近导入的整份副本。旧静态文本保留在存档，但此专精的大秘境由新包接管，避免空白首领继续加载旧提醒；回滚会恢复原接管状态。其他副本、专精和英雄／团本方案不在替换范围。

新草稿的所有首领均为空白，没有专精打法预设或快捷技能。药水与饰品可自行添加为文字提醒；填写物品编号或饰品槽、且其使用技能编号公开时，才能自动撤对应提醒。尚未接入特殊事件的首领提供开战相对安排，不能任意命名一个事件就认为游戏能识别。

团本在 [Lorrgs](https://lorrgs.io/) 选择玩家和技能，复制MRT／NSRT并直接粘贴进插件；网页只有这个入口提示。动态导出仍需核对阶段绑定。开发用WCL命令行工具保留，但网页不再读取日志，也无需日志才能生成。

本地网站没有公开部署、账号或全专精打法推荐库。执行者自检完成，待 Advisor 验收；STATIC/MOCK及浏览器范围见PROJECT_STATE，游戏LIVE未测。协议见docs/WEB_PLAN_FORMAT.md。

## 首次事件后的冷却语音（0.2.1）

在第一次易伤的大军和突变行勾选“后续冷却就绪提醒”。实际用过该行技能后开始监听，之后每次观测实际冷却结束显示提醒并报一次“技能好了”；起手同技能不会提前开启易伤后的监听。它只读取公开冷却布尔状态，未知/秘密/接口异常时不猜秒数；充能技能恢复满充能后才提醒，物品和文字不支持后续模式。整副本方案内保留NRPlan:2，插件兼容旧NRPlan:1；勾选后重新生成并复制导入，旧版插件须升级。游戏播放窗的“模拟冷却结束”仅用于演练。LIVE未测。

## 大秘境没配置的首领

不用每只首领都配置。大秘境里，**你配置过的首领按你的方案走**（网站整副本方案或单首领方案）；**没配置的首领**自动使用内置爆发提醒：

- 开打时提醒当前专精的主要爆发技能（覆盖 40 个专精，包含可选天赋，只取你已学会的）。
- 用过以后，每次冷却好了再提醒一次（语音“××好了”）。开打时没按、过了一会儿才第一次用，也会从那次开始跟踪。
- 只在大秘境生效，团本和普通史诗不会自动提醒。
- 不想要可以在设置页取消“大秘境没配置的首领：开打和每次爆发好了都提醒”。

0.3.11-dev 起，可在游戏输入 `/nr` →「提醒设置」→「大秘境默认爆发」→「编辑技能」自行修改当前专精名单：右侧点「添加」、左侧点「删除」，也可输入技能编号或粘贴技能链接加入目录外技能。每次操作立即保存，下次未配置的大秘境首领生效。不同专精分别保存；删空表示不提醒任何默认爆发技能；「恢复内置默认」重新跟随插件默认名单。未学会的技能会过滤，战斗中不能修改。导入新方案时，已自定义名单的专精会跳过从内置默认名单中删除的技能，并提示跳过条数；方案中额外安排的非默认技能保留。已保存的旧方案不回溯修改。

## 从 Lorrgs 导入

建议第一份方案使用 **MRT（Method Raid Tools，团队安排工具）静态导出**，即以开战为时间起点。

1. 在 Lorrgs 选一名玩家，只勾选需要提醒的技能，打开 Copy Note。
2. 选择 MRT，关闭 Dynamic Timers，复制网站正式生成的文本。
3. 游戏输入 `/nr`，填写首领 EncounterID（首领战斗编号），选择“使用难度”，粘贴文本。默认“随导出”对 MRT 使用史诗／大秘境，因为 MRT 文本不包含难度。
4. 保持“作为我的个人方案”勾选，点击“检查导入”，在右侧核对首领、难度、条数和时间，再保存。

NSRT（Northern Sky Raid Tools，另一种团队安排工具）格式自带首领编号和难度，也能粘贴导入。它可能使用阶段相对时间，需要下面的绑定步骤。

### 动态阶段（推荐 NSRT）

Lorrgs 对部分团本首领（当前为奈克扎利 3470、墓葬哨兵 3445、盘绕祭坛 3429、失落探险者 3497）按阶段导出，阶段号可能是 1.5、1.75、2.5。时间从**那一阶段开始**算，所以别的团打得快或慢，提醒都跟着你们自己的转阶段走。

- 检查导入后，右侧每个来源阶段一行。有对应关系的阶段默认是“BigWigs 阶段（自动）”：装了 BigWigs 时，BigWigs 一报转阶段就以那一刻为起点。
- 每行右侧可填“开打后几秒转阶段”（`2:15` 或 `135`）。没装 BigWigs，或开打 5 秒内没收到 BigWigs 时，就按填写的时间提醒；没填的阶段不会提醒，聊天框会提示。
- BigWigs 没有对应的阶段（例如奈克扎利 P1.75 灵魂转移）必须填时间；填了会自动切成“按右侧时间”。也可以点按钮手动选“开打”或“按右侧时间”。
- 其余团本首领 Lorrgs 只导出开打相对时间（全部 P1），直接保存即可。
- 阶段对应关系由本项目依据 Lorrgs 阶段规则和 BigWigs 模块整理，**秒级偏差尚未实测**，第一次用请在实战中核对。[Lorrgs 导出实现](https://github.com/gitarrg/lorrgs-frontend/blob/main/src/components/CopyNoteWindow.tsx)

史诗 Lorrgs 记录也可以用于英雄：把“使用难度”从“随导出”切为“英雄”，重新预览并保存。NSRT 保留原始来源难度，预览同时显示“用于英雄（来源史诗）”；英雄和史诗方案分别保存。使用难度只决定在哪种战斗加载，**不换算施法秒数，也不推断跨难度阶段**。需按英雄实际机制调整时间；例如原包乌拉特克心脏第一次施法预报英雄 129 秒、史诗 139 秒。建议选择目标难度的记录，或手动校正导出文本里的时间后再导入。

示例仅用于验证导入格式，不是首领爆发建议：

```text
EncounterID:3492;Difficulty:Heroic;Name:Ulatek;
ph:1;time:135.5;tag:TopPlayer;spellid:51271;
```

同一首领同一难度保存一份方案，新导入会替换它并保留一份备份。“暂停此方案”和“回滚”作用于**最近保存的方案**；重新保存可恢复启用。

个人模式忽略来源玩家名字，所有导入技能都提醒自己。因此请一次导入一人的必要技能。取消个人模式后，仅匹配自己的名字、职业、专精、职责或队伍编号；这是自己的筛选提醒，不会向全队分发方案，也不会检测队友施法。

## 从 WCL 生成（大秘境 / Lorrgs 没有的首领）

Lorrgs 只有团本。`tools/wcl_note.mjs` 直接读 Warcraft Logs：取排行里带日志的高手，截取指定首领那一段，输出插件可直接粘贴的 NSRT 文本（自带 EncounterID 和难度）。WCL 凭据复用 rotation-lab 的 `configure_wcl.ps1` 配置。

```powershell
# 大秘境：副本排行第 1 份带日志记录，密谋小径老一（3101）
node tools/wcl_note.mjs top --dungeon "Murder Row" --boss 3101 --class DeathKnight --spec Frost --copy
# 团本：首领排行（--difficulty 5 史诗，4 英雄）
node tools/wcl_note.mjs top --boss 3492 --class DeathKnight --spec Frost --difficulty 4 --copy
# 指定某份报告、某场战斗、某个玩家
node tools/wcl_note.mjs report https://www.warcraftlogs.com/reports/<code>#fight=5 --boss 3101 --player <名字> --copy
```

WCL 没有技能冷却数据，默认只保留两次施法总是间隔 ≥45 秒的技能（爆发、药水、饰品等）。终端会列出选中项；加 `--list` 看全部技能，用 `--spells 51271,439843` 精确指定，`--exclude 47528` 排除，`--min-gap` 调阈值，`--rank 2` 换第二份记录。`--copy` 复制到剪贴板，游戏里 `/nr` 粘贴即可，无需填首领编号。

时间 0 是 WCL 记录的该首领开打时刻，与游戏 ENCOUNTER_START 可能差约 1 秒。大秘境排行按整个副本排名，所选玩家在这只首领不一定打得最好。

## 不打团本也能播放预览

1. 脱战 `/nr`，粘贴团本导出，选择使用难度，点击“检查导入”。
2. 点击“播放预览”。无需先保存，打开播放窗口后自动从开战 0 秒开始。
3. 可以暂停/继续、1/2/4 倍速播放、输入秒数跳转。窗口显示全部提醒的技能、来源阶段、相对时间和当前状态，可滚动查看。
4. 用上面的示例，可直接跳到 **125 秒**：看冰霜之柱提醒（提前显示 10 秒），125.5 秒出现，129.1 秒念「准备爆发」，130.5 秒起 5、4、3、2、1，到 135.5 秒显示“现在”。提醒上带“预览”标记。
5. 每行“已用”模拟成功施法，撤掉正在显示的相同技能提醒，不消耗后续提醒。关闭窗口、点停止、播放结束或进入战斗时清理预览。

阶段相对提醒不会猜测阶段发生时间。点击“进入：……”在当前模拟时点手动进入对应阶段；未绑定到实战的团本阶段也可以单独演练。手动阶段只用于预览，保存到实战仍要通过完整阶段绑定校验。已绑定的节点按节点顺序演练，同节点的多行一起触发。

跳转会重建当前模拟状态，跳过已经结束的提醒；向前跳不会补播沿途所有声音。向后跳会丢弃该时点之后的手动阶段和模拟施法，随后可重新演练；“重新播放”清掉整轮预览操作。预览最长 7200 秒。

语音、倒数和发光使用真实显示逻辑。单人时填 `player` 可验证自己的框；没有真实团员框体时无法检查指定团员的框。预览不保存或修改个人方案，不影响实战引擎/日志。它能检查提醒行为，阶段的真实识别时点仍需游戏实测。

保存后也可用 `/nr preview` 播放最近保存的方案。阶段绑定区域可以滚动，播放窗口可演练导出的全部阶段；尚未完整绑定的方案不能保存到实战。

## 语音和倒数

默认提前 10 秒显示（填多少就是多少；不足 7 秒时不念「准备爆发」，只念 5…1），施法时点后保留 5 秒，提示音效默认开。旧默认值（提前 5、保留 10、音效关）会自动换一次，自己改过的不动；设置可修改提前量和保留时间，并分别开关用过隐藏、语音倒数（准备爆发 5…1）和提示音效。

音效在「提醒设置」的「提示音效」下拉菜单里选（总开关是「提示音效」开关），点一项会先试听一次，旁边「试听」可以再听：
- 只列插件自带的语音包：默认诺艾尔「快按爆发」；也可选李云龙「开炮！开！炮！」、御女茉莉「哥哥！该放大招了哦！喵喵」「好舍不得你的大招哦！哥哥！」、宣传片「该放大招了」（两版）、丽塔「大招好了」，或「不播放」。原来选的语音已从包里移除（喵喵、李云龙第二版、御女茉莉两条第二版）的，会自动换成诺艾尔。
- 不列魔兽自带音效和其他插件（如 Rurutia 语音包）登记的共享音效，也不再支持自定义文件，避免列表过长、多占内存。以前选过这些的，会自动回到默认语音。
- 列表里每条右侧的 × 可删除不想要的语音（立即生效，删掉的不再列出、不再播放；「不播放」不能删）。删了正在用的那条会换到诺艾尔或下一条。列表底部「恢复已删除的语音」一次全部找回。
- 提醒显示在屏幕上方偏中（第一条顶边在屏幕高度 16% 处），实战和 `/nr test` 位置相同；只有打开预览播放窗口时，为了不被窗口挡住才移到屏幕最上沿。
- 顺序是：提醒提前出现 → 剩 6.4 秒念「准备爆发」→ 5、4、3、2、1 → 到点播放选中的语音。倒数是诺艾尔录音（`Media/prep_burst.ogg`、`count_1～5.ogg`）。技能还没转好时不念「准备爆发」；提醒出现时已不足 6 秒时直接从数字开始。技能转好的提醒出现时直接播放选中的语音。几条提醒同时到点只放一次；提醒出现时已经到点（比如技能转好的提醒）就立刻播放。

插件只播放自带录音，不使用游戏的文字转语音（念技能名已移除），也不再有语音音量设置（录音按游戏主音量播放）。团框发光功能已移除。

成功使用对应技能只撤掉**已经显示**的个人提醒，后续同技能提醒不受影响。若游戏返回秘密技能值，插件跳过该值，提醒会按保留时间结束。

## 面板与战后收尾

设置窗口和播放窗口是浅色卡片界面：左侧图标栏（导入／设置／播放最近方案），顶部切换页和「提醒总开关」。圆角、阴影和图标是插件自带的高分辨率贴图（`Media/ui_*.tga`，由 `tools/make_ui_textures.py` 生成，8 倍超采样）。不进游戏也能看布局：`python tools/render_ui.py` 用真实布局代码画出 `docs/ui-*.png`。

关闭设置窗口或播放窗口、首领战结束时，插件会停止残留语音并清空提醒和监听；战斗中延后处理，预览播放中不打断。插件不再强制回收 Lua 内存，也不提供“清理内存”按钮或 `/nr gc` 功能；不用的数据交给 Lua 正常回收。

注意：语音文件解码后由游戏的声音系统缓存，不算在插件内存里，插件只能停止播放，不能从游戏里卸载它；插件列表里看到的占用是插件自己的 Lua 数据。

## 我们自己的数据怎么维护

程序、首领数据 `BossData.lua`、个人方案 `NextRemindersDB` 分开保存。个人方案在游戏 SavedVariables 中，不在安装 ZIP 内。

从我们的游戏实测、公开事件记录和 Lorrgs 记录核对新时点/阶段，在 `NextReminders\BossData.lua` 修改固定预报或识别规则，并更新独立的 `dataVersion`。新增规则补充公开事件回放测试；通过 `python tests/check.py` 后执行 `python tools/build.py`，生成新包覆盖安装。具体步骤见 `docs/DEVELOPMENT.md`。

已有历史基线保留，原插件的 ZIP 更新工具及指纹 manifest 已从当前源码移除，旧版源码包保留历史。个人施法秒数仍来自自己的导入文本；修改首领预报不会自动修改个人安排，需要编辑导出文本或重新从 Lorrgs 导入。
