# NextReminders 错误记录

## NR-ERR-026：输入已聚焦，但导入区仍看不到插入光标

- 状态：修法已实现，0.3.5，STATIC/MOCK通过；真实游戏光标像素LIVE待复核。
- 现象／已确认缺口：用户0.3.3游戏截图显示“正在输入”及蓝边框，却仍无法看到文字插入位置。0.3.3只新增焦点反馈和滚动，完全依赖原生光标绘制；旧MOCK没有验证任何可见光标对象。截图无法排除原生光标正处于闪烁隐藏帧，不能宣称已查明客户端内部的完整原因。
- 修复：导入EditBox内增加2单位宽的冷蓝插入光标，空文本聚焦立即在左上文字起点显示；非空文本只采用原生OnCursorChanged的公开x/y/height，不估算中文或换行宽度，随ScrollChild一起滚动裁剪。每0.5秒闪烁，移动时立即亮起；失焦、Esc、切页、隐藏停止更新并撤掉光标。显式初始化空文本／插入位置和左上对齐，原生输入继续负责打字、选择及粘贴。
- 适用：UI方案导入，NR-ERR-020为焦点／滚动历史修复，不能再把它的MOCK当成可见光标已游戏验证。
- 避免：用户要求插入光标时验收具体可见位置和生命周期，不能只断言HasFocus或状态文字；原生布局回调与文本回调两种顺序均处理，未知／秘密坐标不绘制伪位置。插件UI修复不能拿HTML样稿代替游戏像素验证。
- 验证：实际UI代码空框点击→可见光标→闪烁，原生长文坐标与滚动，Cursor-before-Text回调顺序、未知坐标、焦点转移／Esc／切页／隐藏清理及原文本不变。统一入口49项STATIC/MOCK通过；备份并同步实际游戏安装，LIVE未测，source_review=PENDING。

## NR-ERR-025：Windows本地服务器把WebP技能图像标成普通文件

- 状态：FIXED，0.3.4，STATIC/WEB。
- 现象／根因：技能图像本地请求HTTP200，但Content-Type为application/octet-stream。Handler只显式注册模块脚本和CSS，Windows的系统MIME库没有标准WebP映射；当前浏览器仍能渲染，不把此现象误记为已经发生图片白屏。
- 修复：Handler显式注册WebP、PNG、JPEG和SVG图像类型。
- 适用：本地网页资源服务、技能／品牌图像。
- 避免：新增资源格式时检查真实HTTP类型，不只看200或当前浏览器的容错渲染。
- 验证：入口检查WebP/PNG映射；重新启动此任务服务器后请求51271.webp返回image/webp。最终构建48项通过，游戏逻辑无改动。

## NR-ERR-024：手填技能编号时卡片标题仍短暂显示旧技能

- 适用：网站手填技能／物品／文字与内置目录混用。
- 避免：数据在input生效时，同一数据的可见摘要也同时更新，不能让旧技能标题暗示实际会导出旧技能。
- 验证：WEB选择冰霜之柱后手填999999，未失焦时标题立即为技能999999，导出含999999；重新填目录编号后恢复对应中文名与图标。与48项入口一起交付，LIVE无关。
