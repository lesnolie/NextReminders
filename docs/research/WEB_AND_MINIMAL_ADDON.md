# 网站与最小插件的职责

2026-10-12最终用户范围（0.3.0）：网站只做大秘境首领配置，团本直接去Lorrgs复制MRT／NSRT。本文后部为0.2.0历史草案，不能据此扩展本次网页范围。

网站负责专精／副本目录、逐首领事件和动作配置、显式生成、快照预览、整副本复制以及本地草稿。插件负责全包校验／范围替换／备份回滚、首领和专精匹配、公开事件识别、提醒显示与声音。目录不等于所有机制已支持；已有识别候选仍待LIVE。

2026-10-12。用户提出网站类似Lorrgs，包含所有专精并导出可复制MRT/NSRT；随后明确另保留本插件完整事件格式。0.2.0已形成本地网站与插件导入链路，验证范围见PROJECT_STATE；本文记录职责划分，不代表共享服务或全专精推荐库已完成。

网站负责：专精/首领/难度筛选、日志展示、个人安排编辑、机制相对安排、方案版本与导出。团本范围为全首领，未来新增首领可接；大秘境只含首领战。所有专精是目录与编辑目标，不能把选项存在说成已有全部专精的真实推荐数据。

插件负责：识别首领/难度/专精、解析粘贴数据、根据自有公开事件执行方案、提醒/声音/倒数/撤掉已用提醒。首领信号定义与个人策略分开。建议主界面只保留粘贴、导入、预览和启用状态；声音/位置/缩放作为少量本地偏好，避免每次换网站方案覆盖用户本地选择。用户尚未确定是否保留这些偏好入口。

Lorrgs的公开CopyNoteWindow源码按选择的个人施法生成MRT时间行或NSRT头部与phase/time/tag/spellid行。动态导出使用来源场次的阶段起点；来源阶段号不能直接变成本插件确认的易伤/召唤节点。本文的结论只针对Lorrgs同款导出，不宣称完整MRT/NSRT产品没有其他扩展能力。

来源：https://github.com/gitarrg/lorrgs-frontend/blob/main/src/components/CopyNoteWindow.tsx （2026-10-12读取）。当前NextReminders Import.lua只认可上述受限字段和显式本地阶段绑定，不能从普通施法秒数自动推导“只等第一次易伤、之后解除保留”。

用户已选择：通用MRT/NSRT导出之外另提供本插件完整事件方案导出。0.2.0定义NRPlan:1，具体合同见../WEB_PLAN_FORMAT.md；通用导出不静默删掉无法表达的事件规则，不把私有扩展冒充通用兼容文本。用户操作保持“网站复制→插件粘贴”。
