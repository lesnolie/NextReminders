# WCL 全首领阶段审计（2026-10-23）

范围：至暗之夜第 2 赛季 28 只大秘境首领 + 10 只毒牙深渊团本首领。WCL v2 GraphQL 每只读取 3 份跨区击杀；团本读取 `phaseTransitions`，大秘境因该字段为空或缺失，改用本体/目标首领施法、客户端血量阈值与时间轴状态机交叉判断。

## 结论

- 38 只首领已覆盖：28 只大秘境、10 只团本。
- 16 只有可解释的真实阶段模型；其余 22 只当前按事件处理。
- 7 只团本由 WCL `phaseTransitions` 直接确认。
- 大秘境 WCL 报告没有可直接使用的阶段转换字段；“血量阈值触发一次机制”不自动等于“进入一个持续阶段”。
- 团本 8 号 Ula'tek（乌拉特克）确有 P1→P2→P2.5→P3；之前感觉不到，是因为原来的 NSRT 全为 `ph:1`，所有提醒一直从开打计时。
- 全 `ph:1` 的旧记录不能按平均 WCL 秒数静默拆阶段。必须有 WCL 阶段字段或已确认的客户端边界；网站兼容层会返回“需要显式阶段边界”。

## 状态说明

- **WCL 直接确认**：报告 `phaseTransitions` 有阶段 ID 和起点。
- **WCL + BigWigs 对齐**：WCL 阶段结构与客户端大阶段值一致，但游戏内消息仍应 LIVE 核对。
- **客户端规则 + WCL 事件支持**：WCL 看到阶段专属技能/形态，客户端还有血量或事件规则；阶段语义仍需 LIVE。
- **仅事件**：当前没有足够证据证明有持续阶段，照普通技能、召唤或易伤事件提醒。

1. 插件新增 Ula'tek：Lorrgs/来源阶段 P2/P2.5/P3 分别绑定 BigWigs stage 2/2.5/3；新增 Kith'ix：来源 P2 绑定 stage 2。
2. 旧 NSRT 里的 `ph:1;time:X` 不会自动变成阶段相对方案，因为文件本身没有“P2 从几秒开始”的信息。
3. 网站新增单首领 NSRT 转换入口和 `web/nsrt-compat.mjs`：保留任意两位小数阶段；只在用户填入 WCL `phaseStarts` 时，把全 P1 的时间转换为本地阶段 + 阶段内偏移，并保留 `absoluteTime` 供逐行核对。填 `1=0, 2=174.1, 2.5=318.9, 3=339.5` 即可处理上面的乌拉特克样例。
4. Sszorak（3420）虽有 WCL P1↔P2，但 BigWigs 没有 `SetStage`；当前不伪造自动绑定。
5. 失落探险者（3497）的 WCL 临时阶段 ID 会在不同样本中变化，必须按切换顺序处理。
