# 全团本与大秘境通用机制平台范围

日期：2026-10-12。用户将目标明确为全部团本、后续新首领、大秘境，而不是单一H8案例。本次形成通用范围和数据源调查；没有修改产品运行代码，当前包仍为0.1.3。

用户补充范围：大秘境只接首领战。目录、记录、导入、阶段识别、校准和提醒以单次首领战为单位；不采集路上的小怪战、不建立拉怪路线或整趟钥匙时间轴。首领机制召唤的小怪仍作为首领机制处理；层数等环境信息仅用于首领战的分组和校准，不扩展为整本路线系统。

## 目标与接入过程

所有首领使用相同流程：发现首领 → 采集公开事件/导入日志 → 建立初始机制模型 → 核对节点身份 → 本场对齐/跨场校准 → 回放与LIVE验证 → 更新独立数据版本。

首次遇见未知EncounterID时，可自动建立目录和记录；没有证据的机制保持未知。新团本和赛季复用采集、校准、导入和提醒引擎；主要增加数据与有依据的规则。无法表达的新事件组合才扩展引擎，并补相应合同和回放测试。

目录、时间表、实时识别与实测是不同覆盖维度。目标“支持全部接入”不等同“首日全机制均已精确识别”。新首领出现时可以立即记录并使用开战相对基础提醒，准确的阶段/机制节点随后验证。

## 通用模块

| 模块 | 职责 | 接口边界 |
| --- | --- | --- |
| 首领目录 | 当前及未知首领、实例/难度/版本、各类覆盖状态 | 不参与机制推断；不把BossData中的7只作为采集白名单。 |
| 战斗记录器 | 持久保存公开事件、状态变化、预测、候选和确认标签 | 不记录秘密字段；标记截断/缺失/模拟，保留原始数值来源。 |
| 来源适配 | 本地公开记录、WCL、可核对公开项目数据 | 不直接运行上游代码；区分玩家施法和首领机制，显式映射ID/难度。 |
| 机制模型 | 节点含义、轮次、事件组合、固定/相对时间和来源 | 稳定机制键替代匿名计时id；阶段种类与发生轮次分开。 |
| 校准 | 已确认节点的误差统计、未来时点重排、变化检测 | 不以自己的预测作真值，不混合难度/构建/不同机制轮次。 |
| 规则评估 | 新候选后台计算、标注回放和误报/漏报统计 | 不先接管正式提醒；用未用于拟合的样本验证改进。 |
| 个人提醒 | 相对某机制节点的个人施法偏移 | 不把高手施法当机制真值；静态时间安排与机制相对安排分开。 |

采集元数据应包含：EncounterID、原始游戏难度、实例/挑战地图、大秘境层数/影响机制的环境、游戏构建、数据和规则版本、真实/模拟标志。某字段不可取得时明确缺失，不能用0或默认值假装已知；足以影响正确性的分组缺失时停止自动合并。

## 自动变准的边界

可自动校准：已独立确认身份的固定机制时点、相对可靠节点的间隔、已确定规则的误差统计。阶段开始已确认后可以同步该段未来预测，不能一律平移全场或追回已响提醒。

新阶段规律：自动生成事件组合候选，但需要独立标签判定含义与正确性。单次计时移除、玩家施法、另一个使用相同匿名特征的预测，都不能独立证明实际机制。打断/击杀速度决定的机制优先相对节点建模，不把所有绝对秒数平均。

排除模拟样本、重复事件、无法确定身份的匹配；中途结束后未观察到的事件不记为零。补丁后出现明显变化时暂停旧校准并重新分组验证，保留旧模型版本。没有数据的新首领不承诺自动理解全部机制。

## 当前可用的公开来源

2026-10-12核对GitHub完整目录（均truncated=false）：

- [BigWigs](https://github.com/BigWigsMods/BigWigs)，master快照 `aed9bf5187a07852b94228572234bcd4909f13f0`。当前有TheVenomousAbyss/Ulatek.lua及其他团本文件；该文件按难度订阅公开时间轴事件，并有阶段判断。可调查机制身份、信号和初始规则，不能将他人代码存在当成本插件LIVE已验证。
- [LittleWigs](https://github.com/BigWigsMods/LittleWigs)，master快照 `2777a9d51418934b5fdd5b92d937b1af6070bcad`。有Midnight/AltarOfFangs等五人本首领模块，适合作为大秘境机制调查线索。
- [Northern Sky Raid Tools](https://github.com/Reloe/NorthernSkyRaidTools)，main快照 `078d0dc15c167c197c740a3a7b760d3bbe4e6761`。BossTimelines/MidnightS1与MidnightS2有多个首领的难度时间表；[Nymrissa示例](https://github.com/Reloe/NorthernSkyRaidTools/blob/078d0dc15c167c197c740a3a7b760d3bbe4e6761/NorthernSkyRaidTools/BossTimelines/MidnightS2/NymrissaWavecaller.lua)分别定义Heroic/Mythic阶段与能力时间。默认阶段时间表不等于实时阶段识别信号。
- Warcraft Logs（WCL）：现有本地tools/wcl_note.mjs读取个人施法并生成导入文本。通用机制数据还需要敌方机制事件、阶段及时间起点的独立适配；当前个人导出工具不提供这种真值。官方API文档网页本次返回403，未据此推断schema或可用权限。
- 游戏公开时间轴：跨首领采集统一匿名实例、来源、公开时长和状态；其语义仍需验证，秘密值不读取。

不依赖TimelineReminders新版获取；其他公开项目是候选证据和初始数据来源，不自动成为运行依赖，也不整包复制。

## 实施阶段

1. 通用目录与持久记录：不限现有BossData白名单，无个人方案也采集；观察未知首领可持续记录，不误报已识别。大秘境以首领开战到结束为采集边界，不触发路上小怪战的记录或提醒。
2. 标注/日志导入与机制模型：先形成能回放评估的节点身份和样本。
3. 已知节点的本场同步、跨场统计校准与机制相对提醒。
4. 补当前团本/大秘境数据，展示每只首领的实际覆盖与精度；新赛季使用相同接入流程。
5. 有独立标签后再加入新规则候选的自动生成和验证。

各阶段以通用接口实施，不能将整体需求缩水为只做H8。阶段完成范围、STATIC/MOCK/LIVE和当前模型版本分别报告。当前尚未开始上述运行模块实施，不宣称全首领或自动学习已支持。
