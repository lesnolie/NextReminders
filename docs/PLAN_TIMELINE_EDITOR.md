## 2. 目标与首个闭环

默认流程：

```text
导入 NSRT → 根据时间轴区域自动建议阶段／机制绑定 → 手动拖动或改字段
→ 可选 WCL 校准 → 导出 NRPlan:3 → Lua 校验、保存、模拟调度
```

首个可测试闭环使用乌拉特克（3492）：

- 保留导入行的原始 `ph`、`time`、`spellid`、`tag`，包括 `1.5`、`1.75`、`2.5`。
- 网站显示开战时间轴、大阶段轨道、具体机制轨道和技能点。
- 技能落在已知规划区域时自动建议绑定；区域没有预计起点时要求手动填写。
- 拖动和字段修改可撤销／重做。
- WCL 仅作可选校准，不是导入或导出的前置条件。
- 导出 `NRPlan:3`，Lua 能校验、保存并在模拟运行时按开始／阶段／机制／次数／偏移调度。
- 提前于机制的负偏移只有在预测源已接入，或明确填写固定开战时间兜底时才允许实战。

## 3. 统一数据模型

### 3.1 共享首领规则源

唯一维护源：`web/boss-rules.json`。

生成物：

- `web/boss-rules.mjs`：网站导入。
- `NextReminders/BossRules.lua`：插件运行与校验。

`tools/sync_boss_rules.py --check` 必须验证两个生成物与 JSON 完全同步。规则至少描述：

- 首领编号、名称、数据版本。
- 大阶段：ID、标签、预计起点、BigWigs 映射或“未接入”。
- 具体机制：ID、标签、发生次数、预计时点、施法／易伤持续时间、预测来源、支持级别和证据状态。

证据状态必须显式，不能把“固定参考”或“候选映射”写成 LIVE 已通过。

### 3.2 NRPlan:3

头部保留现有字段，并新增规则数据版本：

```text
NRPlan:3;EncounterID:3492;Difficulty:mythic;SpecID:252;Name:Ulatek;RuleVersion:2026.10.23.1;
```

每行包含：

- `anchor:start`、`anchor:stage:<id>` 或 `anchor:mechanic:<id>`。
- `occurrence:1..20|every`。
- `offset:-3600..3600`，允许机制前负偏移。
- `window:0.1..60`。
- `timing:auto|signal|fixed|predicted`。
- `fallback:<开打后秒数>`，用于没有预测源或信号不可用时的明确兜底。
- 原有动作字段：`spellid` / `itemid` / `slot` / `text`。
- 来源字段：`sourceformat`、`sourcephase`、`sourcetime`、`sourcespellid`、`sourcetag`、`sourceraw`。

规则：

- `start` 只能发生一次，且偏移不得为负。
- 负偏移配合 `timing=signal` 拒绝；必须有预测能力或 `timing=fixed` + `fallback`。
- `fallback` 不得伪装成实测；UI 和文档必须标为固定兜底。
- 同一行只允许一个动作。
- 未知字段、未知阶段／机制、重复字段整份拒绝。

### 3.3 存储

新方案只写入：

```text
NR.db.timelinePlans[specID][encounterID:difficulty]
```

不迁移、不覆盖旧 `plans` 和 `eventPlans`。首次加载时只是把该字段初始化为空表；旧 SavedVariables 缺失时行为不变。

## 4. 网站实施

新增独立团本页：

- 首领／难度选择，默认乌拉特克 3492。
- NSRT 导入并逐行保留原始值。
- 横向时间轴、大阶段背景区、机制标记、技能轨道。
- 自动区域建议：按技能绝对时间寻找覆盖它的区域。
- 缺起点区域：显示“需填写区域起点”，不得假装自动算出偏移。
- 拖动技能、修改阶段／机制、次数、偏移和窗口。
- 撤销／重做栈；导入、拖动、字段修改、WCL 校准都可撤销。
- 固定时间兜底与预测来源状态在每行清楚展示。
- 可选 WCL：粘贴人工核对后的阶段/机制时间与报告来源；现有 `/api/wcl` 只有个人施法记录，不能冒充机制校准。
- 导出前显示阻断原因；导出 `NRPlan:3` 并复制。

乌拉特克初始规则只使用现有可追溯资料：

- 被缚之怒读条固定参考：英雄约 129 / 278.1 / 567.2 秒；史诗约 139 / 288 / 583 秒。
- 心脏易伤起点为上述读条后 6.5 秒：英雄 135.5 / 284.6 / 573.7，史诗 145.5 / 294.5 / 589.5。两个机制使用独立 ID 和轨道。
- “被缚之怒”约 6.5 秒读条，随后约 20 秒易伤。
- 这些秒数不是 WCL 阶段校准结果，也不是实时识别已接入。
- BigWigs 大阶段和心脏实时信号未完成本插件 LIVE 验证；默认采用固定兜底，不宣称自动识别。

## 5. Lua 实施

新增：

- `BossRules.lua`：由共享 JSON 生成。
- `TimelinePlans.lua`：解析、校验、存档、查找 NRPlan:3。

调整：

- `Engine`：新增时间轴方案运行行，支持 start／stage／mechanic、次数、偏移、预测与固定兜底。
- `Main`：仅新增时间轴方案查找和加载；旧路径优先级和 M+ 范围逻辑保持。
- `Hook BigWigs`：保留现有公开 `BigWigs_SetStage` 消息；未验证的首领不自动宣称机制识别。
- `UI`：识别 NRPlan:3，显示摘要和保存入口；不在游戏内新增完整编辑器。
- `Preview`：至少能模拟 NRPlan:3 的固定兜底与手动机制事件，用于脱战测试。

## 7. 验收门槛

必须全部满足：

- 原始 NSRT 字段在导出数据中可追溯。
- `1.5`、`1.75`、`2.5` 不被整数化或丢弃。
- 无区域起点的技能进入人工填写状态，不生成虚假偏移。
- 负偏移没有预测或固定兜底时导出被拒绝。
- 撤销／重做覆盖导入、拖动和字段编辑。
- WCL 不可用不影响手动闭环。
- 旧协议测试继续通过。
- 新方案不写入旧方案桶，不修改 SavedVariables 文件本身。
- STATIC/MOCK 与 LIVE 分开报告；未做游戏测试就写 `LIVE NOT_RUN`。

## 8. 风险与处理

- 乌拉特克大阶段起点和心脏信号尚无本插件 LIVE 证据：只做固定参考与模型验证，不宣称实时支持。
- WCL 阶段接口此前超时：WCL 保持可选；失败时显示未校准，不阻断导入。
- 现有工作树携带大量用户修改：所有补丁基于当前文件内容，做完后再次核对 Git diff。
- 旧方案与新方案优先级可能冲突：新方案单独查找，优先只对新格式生效；不迁移或删除旧数据。
- 负偏移的实际可达性易被误解：UI 和导出摘要同时显示 `prediction` / `fixed fallback / unverified`。
